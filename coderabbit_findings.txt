  → Sources/EncoderKit/VideoEncoder.swift:50-68

  The pause gap comes from sample timestamps, not from the clock, so pauses
  are not always removed.

  pause() and resume() both read lastSeenPTS. CaptureSession drops
  idle frames before append. If the screen is static and no audio track is
  active, no samples arrive during the pause. In that case lastSeenPTS
  does not move, gap is zero, and the pause stays in the output as a
  frozen frame. The value at pause can also be old if the screen was static
  before the pause. ScreenCaptureKit and AVCaptureSession both timestamp
  samples with the host time clock. Read
  CMClockGetTime(CMClockGetHostTimeClock()) at pause and at resume, and
  compute the gap from those two values.


  🐛 Proposed fix

       public func pause() {
  +        let now = CMClockGetTime(CMClockGetHostTimeClock())
           queue.sync {
               guard !paused else { return }
               paused = true
  -            pauseStartPTS = lastSeenPTS
  +            pauseStartPTS = now
           }
       }
  
       public func resume() {
  +        let now = CMClockGetTime(CMClockGetHostTimeClock())
           queue.sync {
               guard paused, let start = pauseStartPTS else { paused = false; return }
  -            let gap = CMTimeSubtract(lastSeenPTS, start)
  +            let gap = CMTimeSubtract(now, start)

  major [Stability & Availability]
  → Sources/CaptureCore/CaptureSession.swift:79-85

  Data race: state is written from encoder and ScreenCaptureKit threads
  without synchronization.

  encoder.onError runs on the encoder's private queue, because
  reportFailureIfNeeded is called from inside queue.async in
  VideoEncoder.append. stream(_:didStopWithError:) runs on a
  ScreenCaptureKit delegate queue. Both handlers write self.state.
  stop(), pause(), resume(), and start() read and write state from
  the main actor in RecordingViewModel. State contains a String
  payload. Unsynchronized concurrent writes to state are undefined
  behavior and can corrupt memory. They can also cause stop() to see the
  wrong wasFailed value.

  Choose one owner for state. Either:
  - Run both callbacks on the main actor before they touch state or
  onFailure, or
  - Protect state with a lock.
