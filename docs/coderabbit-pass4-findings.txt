  minor [Stability & Availability]
  → Sources/RecorderUI/GlobalHotkeys.swift:65

  Capture me weakly in the main-queue dispatch.

  The Carbon callback holds an unretained pointer to GlobalHotkey. The
  DispatchQueue.main.async closure captures me strongly. If
  uninstall() runs before that closure runs, the closure keeps the object
  alive briefly and calls the handler after uninstall. The handler then runs
  after the hotkeys were removed. Capture me weakly so the handler does
  not run after uninstall.


  Proposed fix

  -            DispatchQueue.main.async { me.handler() }
  +            DispatchQueue.main.async { [weak me] in me?.handler() }

  minor [Functional Correctness]
  → Sources/RecorderUI/RecordingsListView.swift:87-89

  Remove the duplicate .defaultAction shortcut from the rename Save
  button.

  The sheet header already gives Done the
  .keyboardShortcut(.defaultAction) shortcut. The rename row gives Save
  the same shortcut. AppKit processes key equivalents before the field
  editor gets the key. When the user presses Return in the rename field, one
  of two things can happen:
  - Return triggers Done. The sheet closes and the rename is lost.
  - Return triggers both Save and onCommit. The second commitRename
  then calls rename on the old file.url, which no longer exists, and
  shows a false "Rename failed" alert.

  onCommit already handles Return. Remove the shortcut from Save.


  🐛 Proposed fix

  -                        Button("Save", action: commitRename).keyboardShortcut(.defaultAction)
  +                        Button("Save", action: commitRename)

  minor [Stability & Availability]
  → Sources/EncoderKit/VideoEncoder.swift:329-340

  Serialize VideoEncoder lifecycle state on queue.

  finish() accesses the writer and inputs outside queue, while
  cancel() clears them inside queue. start() also publishes them
  outside queue, while append() reads them on queue. If cancel()
  overlaps finish(), it can cancel and remove the writer while
  finalization still uses it. Serialize start(), finish(), cancel(),
  and all accesses to the writer and inputs through one lifecycle
  synchronization mechanism. Keep those references owned until finalization
  completes.
