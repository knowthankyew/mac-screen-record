  minor [Functional Correctness]
  → Sources/RecorderUI/RecordingViewModel.swift:833-839

  Do not accept .stopping in burnRecording().

  burnRecording() treats .stopping as an active state.
  CaptureSession.burn() treats it differently. Its guard accepts only
  .recording, .paused, and .failed. So session.burn() returns early
  when stop() or the salvage task already owns the session.

  In that case, the view model still deletes targetURL and its evidence
  manifests while encoder.finish() is finalizing the same file. When
  stopRecording() resumes, it sets status = .finished(url) for a file
  that no longer exists. It can also start an Evidence Seal task that fails
  on the missing file. In the salvage path, the code reports "Partial video
  saved" for a deleted file.

  This state is reachable through a race. The menu Stop action and the burn
  hotkey each spawn a Task. The second task can run after status has
  become .stopping. Two quick burn-hotkey presses also reach this branch.

  Remove .stopping from the accepted states. Burn then acts only when the
  session can actually be torn down.


  🐛 Proposed fix

           let isActive: Bool = {
               switch status {
  -            case .recording, .paused, .stopping: return true
  +            case .recording, .paused: return true
               default: return false
               }
           }()
